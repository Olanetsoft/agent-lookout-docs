A Mac that is asleep sends no notification, email, post or push until it wakes. If you step away while a long session runs, the Mac can go to sleep on its own and stop everything quietly. The Mac app has a switch for this: while it is on and at least one session counts, the Mac stays awake. The display still turns off on its usual timer.

This is a Mac app feature. `npx agent-lookout` and `npm start` cannot keep the Mac awake. See [Without the Mac app](#without-the-mac-app) for an alternative.

## Turn it on

1. Open the Mac app and go to Settings (Cmd+comma, or Settings in the Agent Lookout menu).
2. Under Keep awake, set Keep the Mac awake to On.

The app remembers the choice across launches. It is off until you turn it on.

## Which sessions count

While the switch is on, the Mac stays awake as long as at least one session counts. Sessions on this Mac and on every other machine Agent Lookout watches count by the same rules, since this Mac is the one that sends their notifications.

- **A session that needs you** counts for as long as it is listed, however long it has waited.
- **A working session** counts until 30 minutes after its newest update: the newer of when its status last changed and when its agent last wrote to its file. A session with neither time does not count. This 30-minute limit lets sessions that only seem to be working stop counting, such as a Gemini CLI session whose terminal was closed, or a Codex session waiting for approval that shows as working.
- **A working Claude Code session whose process is running** counts for as long as it is listed, with no time limit. Claude Code writes no time while it works, so a limit would let the Mac sleep during a long task. A background job with no running process, such as a `/loop` job between its runs, falls back to the 30-minute rule.
- **Nothing else counts.** Idle, finished, failed, and unknown sessions never count.

The app checks every 2 seconds. It releases the Mac at the first check where no session counts, when you set the switch to Off, or when you quit the app. It never holds more than one sleep assertion at a time.

## What it cannot prevent

Some sleep cannot be held off:

- Closing a MacBook's lid, unless it is plugged in with a display connected.
- Sleep in the Apple menu.
- A battery that runs low.

## Verify it works

Run this in a terminal while the app keeps the Mac awake:

```bash
pmset -g assertions
```

`PreventUserIdleSystemSleep` is 1 or more, and Agent Lookout is listed under the processes that hold an assertion.

## Without the Mac app

`npx agent-lookout` and `npm start` cannot hold a sleep assertion. To keep the Mac awake while either runs, start it with macOS's `caffeinate`:

```bash
caffeinate -i npx agent-lookout
```

The Mac then stays awake for as long as Agent Lookout runs, whatever its sessions are doing. The display still turns off.

## Privacy

The switch stores only whether it is on or off, in `keep-awake-state.json` in the app's data folder. It holds nothing about any session. The sleep assertion is visible to any program on the Mac through `pmset -g assertions`, which shows that some session counted, though not which one. No data leaves the machine for this feature.
