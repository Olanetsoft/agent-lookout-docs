While the Mac is asleep, Agent Lookout is too: it reads no session and sends no notification, email, post or push until the Mac wakes. The Mac app can keep it from going to sleep on its own while your sessions run. Open Settings and, under Keep awake, set Keep the Mac awake to On. It is off until you turn it on, and the app remembers the choice. The display still turns off on its usual timer.

Only the Mac app can do this. `npx agent-lookout` and `npm start` cannot keep the Mac awake.

## Which sessions count

While the switch is on, the Mac stays awake as long as at least one session counts, on this Mac and on every other machine Agent Lookout watches over SSH. The rule:

- A session that needs you counts for as long as it is listed, however long it has waited.
- A working session counts until 30 minutes after its newest update, the newer of when its status last changed and when its agent last wrote to its file.
- A working Claude Code session whose process is running counts for as long as it is listed, with no 30-minute limit. A background job with no running process, such as a `/loop` job between its runs, counts only until 30 minutes after its status last changed.
- Nothing else counts: no idle, finished or failed session, and none whose status is unknown.

The app checks every 2 seconds. It lets the Mac sleep again at the first poll where no session counts, and at once when you turn the switch off or quit the app.

## Status line in Settings

While the switch is on, a line under it in Settings says whether the Mac is being kept awake now and names the sessions that keep it awake. It shows the first three sessions by name, with the machine in words for one on another machine, and counts the rest:

> The Mac is being kept awake now, by checkout-flow, docs-site and api-tests on devbox.

The line changes within a poll or two of a session starting or stopping to count, without leaving Settings.

When no session counts, the line says that none keeps the Mac awake, so it can go to sleep as usual, even while a session past its 30 minutes still shows as working. If the app could not keep the Mac awake, the line says so, and the app tries again every few seconds. Before the app has read your sessions, the line says so.

With the switch off there is no line.

## Check from a terminal

Run `pmset -g assertions` in a terminal. While the app keeps the Mac awake, `PreventUserIdleSystemSleep` is 1 or more and Agent Lookout is listed under the processes that hold an assertion.

## API

The Mac app serves the keep-awake status at `GET /api/app/keep-awake`, under its own address `agent-lookout://app/`. The response is a JSON object with three boolean fields:

```json
{ "on": true, "holding": true, "failed": false }
```

- `on` is whether the switch is on.
- `holding` is whether the app holds the Mac awake now: the switch is on, a session in the last snapshot counted, and macOS accepted the hold.
- `failed` is whether a session counts with the switch on but the hold could not be taken, so the Mac can sleep as usual. The app tries again at every poll.

The response says nothing about which sessions count. Settings works that out from the page's own snapshot.

`POST /api/app/keep-awake/setting` turns the switch on or off. The request body is `{ "on": true }` or `{ "on": false }`. It answers with the same three-field status.

`npx agent-lookout`, `npm start` and `npm run dev` do not have these routes.

## Limitations

Some sleep cannot be held off. Closing a MacBook's lid puts it to sleep unless it is plugged in with a display connected. Sleep in the Apple menu and a battery that runs low also override the hold.

## Alternative for the terminal

To keep the Mac awake while running Agent Lookout from a terminal instead of the Mac app, start it with macOS's `caffeinate`. The Mac then stays awake for as long as Agent Lookout runs, whatever its sessions are doing, and the display still turns off.

```sh
caffeinate -i npx agent-lookout
```
